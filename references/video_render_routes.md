# 动画短片 → 视频渲染：两条路线

这是 `AGENTS.md` 里"可选第八步：把动画短片渲染成视频"指向的方法论文档。这一步**只在用户明确要求"做成视频"时才触发**，不是每次生成剧本都自动跑——生成图片/视频比生成文字要慢得多、也可能有真实成本，不能悄悄发生。

## 版权安全边界（两条路线共用，写在最前面）

两个转换脚本（`scripts/screenplay_to_prose.py`、`scripts/screenplay_to_video_prompts.py`）都**只读取组装文档里"## 二、原创动画短片剧本《…》"到"## 三、创作手法对照表"之间的内容**，不读取"## 一、深度解说词"部分——后者会正常讨论真实电影/导演/历史，绝不能流入图像/视频生成的 prompt 里。这是结构性限制（脚本按标题切段落，不是靠"提醒模型不要"），改动这两个脚本时不要绕开这个边界。

## 路线一：`story-to-handdrawn-video`（手绘风 Remotion 渲染，本机已装好）

### 这个工具要什么

它吃的是**纯中文散文**（`--text` 或 `--input a.txt`），不认识我们的【画面】/台词剧本格式。它自己会把文本按句子切开（`。！？!?；;`），长句再按"后来/然后/于是/但是"这类转折词和逗号继续切，**每一句/每一分句就是一个镜头（beat）**。每个镜头字幕硬性上限45字符，实际按"每行13字×最多3行"折算，超了会直接报错——所以安全上限按约39字算，不是45。每个镜头时长 `clamp(3.8+0.48*行数+0.035*字数, 4.4, 6.2)` 秒，平均约5.5秒。

**它是纯静音的，这是写死在类型系统里的**：`Storyboard.project.audio` 是一个只能取 `{voiceover:'post', bgm:'optional_bed_only', bgm_follows_text:false}` 的字面量类型，校验脚本会直接拒绝任何别的值。渲染器里根本没有 `<Audio>` 组件。也就是说：**没有配音、没有角色声音、没有背景音乐，字幕文字是旁白式的第三人称说明文字，不是台词表演**。配音和BGM是用户自己的后期工作。

输出固定是**竖屏3:4（1080×1440）**，H.264，串行渲染（`--concurrency=1`，一次只渲一个镜头，镜头多了会很慢）。有20种内置画风（见下方 `style_keyword_mapping.md`），不指定就锁定默认 `colored-pencil-diary`。还有两个现成但没人用过的钩子：`--visual-plan <file.json>`（按两位数镜头编号给额外的画面指导，不影响字幕本身）、`--character-lock`（一段贯穿全片的角色一致性说明）。

### `scripts/screenplay_to_prose.py` 做什么

1. 只解析动画剧本那一段（见上方版权边界）。
2. **每次都问范围**，不设默认值，把三档的具体代价摊开给用户选：

   | 档位 | 选哪些场次 | 镜头数估算 | 视频时长估算 |
   |---|---|---|---|
   | `teaser` 预告版 | 1场（高潮/真相反转场，没有明显高潮就用开场） | 约10-14 | 约55-80秒 |
   | `highlight` 精华版 | 4场：开场 + 一轮代表性循环 + 高潮/反转 + 结尾呼应（**永远包含第1场和最后1场**，保住首尾呼应这个结构装置） | 约28-30 | 约2.5-3分钟 |
   | `full` 完整版 | 全部场次 | 约65-110 | 完整6-9分钟，需要明确告知"这是几十次串行出图+渲染，会很慢" |

   场次角色可以按场次标题里常见的词（开场/冷开场、高潮/真相/反转、循环/第N轮、尾声/呼应/收束）做启发式识别，但**识别结果必须打印出来给用户确认**，不能直接生成——选错场次会悄悄破坏首尾呼应这个最关键的结构装置，而且不会报错，只会"感觉不对"。
3. **转写成旁白，不是逐字台词**：每场的【画面】按目标工具自己用的切句/转折词逻辑切成叙述镜头；每句台词/旁白都**改写成第三人称间接转述**（比如"老报时人叮嘱：数字只能往少了喊"，而不是逐字引用原台词）——目标工具的字幕本来就是日记体旁白，不是表演字幕，而且是静音的，硬塞多行对白进39字上限也不会好看。超长的镜头用和目标工具一样的递归切分逻辑处理，避免渲染时报错。
4. 【画面】里除了压缩进字幕的那句话之外的信息（构图、背景、道具），写成一句额外指导，按两位数镜头编号存进 JSON，通过 `--visual-plan` 传进去。
5. 从剧本的"人物"部分自动生成 `--character-lock`，尤其要把"同一个剪影，只换绶带/称谓"这类描述原样编码进去——这些剧本里，视觉一致性本身就是揭示"换汤不换药"的情节装置，不是单纯美观问题，几十个镜头下来一旦跑偏，这个反转就废了。
6. 读剧本"项目信息→形式（视觉风格关键词）"这个字段，对照 `style_keyword_mapping.md` **推荐3-5个候选画风**，不直接锁定一个——选错画风意味着要重新出一遍图，这个决定应该让人看一眼再定。

### 每次运行前要明确告诉用户

- 出来的是**静音视频**：没有配音、没有角色声音、没有配乐（只能自己后期加一条纯配乐底）。台词会变成转述字幕，不是表演。
- **竖屏3:4**，不是16:9横屏。
- `full` 档尤其要提醒：几十步串行出图+渲染，建议通过目标工具自己的 `plan → generate → import → render` 分阶段跑，而不是一次性阻塞调用，方便中途检查和续跑。

## 路线二：即梦 / Seedance 等文生视频（目前只做到"生成可粘贴的 prompt"）

### 现状

这台机器上**没有**接入即梦、Seedance 或任何类似服务的 MCP、插件或 API key——搜过 ToolSearch、MCP registry、`~/.claude/skills`、`~/.claude/plugins`，以及整个 workspace 底下的配置文件，都没有找到。所以第一阶段不做自动化，只做"生成一份能直接粘贴进这些工具网页版的 prompt 文档"。

### `scripts/screenplay_to_video_prompts.py` 做什么

同样只解析动画剧本部分（版权边界同上）。和路线一不同，这里**不需要切成5秒一镜的散文**——即梦/Seedance这类工具的网页版 prompt 本来就是按"一场戏"给指令的，信息密度可以更高。脚本给**每一场戏生成一个 prompt 块**（全部场次都给，这里没有路线一那种"镜头数=出图次数=成本"的压力，不需要分档），每块包含：

- 【画面】提炼出的镜头描述
- 一句建议的运镜方式
- 台词处理成"画面里出现字幕"的指令（不假设这些工具支持配音——不同工具处理方式不一样，这里只是标注建议，不替用户下判断）
- 文件开头统一放一段风格/角色"设定说明"，保证贴给工具时几个场次的画风、角色形象能保持一致

输出是一份现成的 `.md` 文件，不锁定即梦或 Seedance——用户自己选工具粘贴，其他类似的文生视频工具也能用。

### 后面两个阶段，这一轮不做，只记录在这里

- **阶段二·半自动化**：用已有的 `mcp__Claude_Browser__*` 浏览器工具去操作即梦/Seedance网页版，前提是用户已经登录好了会话（Claude 不会替用户输入登录凭证）。
- **阶段三·真正的API自动化**：走火山引擎 Ark 平台（`ARK_API_KEY`），要么用 `anthropic-skills:mcp-builder` 自己搭一个 MCP，要么用插件市场里现成的 `runway-api`（已经代理了 Seedance 2）或 `togetherai-skills`。

这两阶段都需要用户先有账号/凭证/明确的目标平台，现在没有任何一项条件满足，先不搭空壳代码——阶段一的"生成 prompt"这个最小可用版本先跑起来，看实际用不用得上，再决定要不要往下建。
