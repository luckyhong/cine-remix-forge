# 交互式可视化页面：设计与生成指南

这是 `AGENTS.md` 里"可选第九步：发布成交互式可视化页面"指向的方法论文档。这一步**只在用户明确要求"做成网页"/"可视化一下"时才触发**，不是每次生成完文档就自动跑。

## 前提：这个能力依赖宿主环境，不是所有工具都有

跟 Step 8（视频渲染）不同，这一步不靠 Python 脚本，靠的是宿主 agent 工具自身"发布可交互网页"的能力（Claude Code 里是 Artifact）。**如果当前工具没有这类能力（比如纯终端里的 Codex CLI、没有画布功能的场景），直接告诉用户这个工具做不到，不要退而求其次生成一个本地 HTML 文件草草了事**——一个不知道存在哪儿、没人会打开的本地文件，价值约等于零，比诚实说做不到还糟。

如果宿主是 Claude Code：动手写页面前必须先调用 `artifact-design` 技能，拿到当前这次发布该走的设计规范，不要跳过。

## 这个页面要展示什么

不是把 markdown 文档整个倒进一个网页模板——那样和直接看 `.md` 文件没有区别，价值为零。这个页面的价值在于把三处**结构化但纯文本很难一眼看出规律的东西**变成真正可视化的形式：

1. **全片时间轴总览**：把解说词的分幕时间戳画成一条横向时间轴，每一幕占片长对应比例的宽度，标出幕标题。让读者第一眼就能确认"开篇钩子/结尾升华各占10-15%，中段幕越往后越短"这类结构性要求是不是真的落地了，而不是逐行读时间戳去心算。

2. **单幕画面/文案对齐条**——整个页面里最有价值的一块，直接把"分镜密度"规则变得肉眼可见：每一幕做一条对齐条，narration-covered 的区间和 gap-filling 分镜区间用不同的视觉样式区分（比如实色块代表有台词的区间，带纹理/描边的块代表纯画面的分镜手法），标注具体用了哪种手法。这是文字格式完全做不到的——一段"90秒的幕，前12秒定格+沉默反应镜、中间43秒念文案、后35秒空镜+资料闪切"，读文字要心算三次，看这条对齐条一眼就懂。

3. **创作手法对照表，做成对照图而不是表格**：现有的 markdown 表格逐行列"手法/解说词处理/动画剧本处理"，可视化版本应该让两栏能对着看——左右两栏卡片，中间用连线或对齐的行高把对应的手法连起来，尤其是"首尾呼应"这一行，尽量直接引用两边呼应的具体句子/符号，而不是只写"有呼应"三个字。

其余信息（用的哪个叙述人设、生成日期、片名）放在页面顶部一个简洁的 header 里就够，不用做成视觉重点——**这个页面的主角是结构，不是装饰**。

## 语气必须跟着内容的分量走，不能一律做得"热闹讨喜"

这是最容易出问题的地方。这个 skill 生成的电影往往涉及真实的历史创伤（参考示例本身结尾就是导演、原著作者真实的迫害与自尽记录）——可视化页面的配色、字体、动效都必须跟着这部电影/这一幕的严肃程度走，不能因为"要做得吸引人"就默认套用明快活泼的配色和跳动的动效。内容越沉重，页面的视觉语言应该越克制、越像一份排版严谨的文献，而不是一张信息图海报。这条判断每次生成前都要重新做一遍，不能套用上一次用过的基调。

## 版权边界：和其余步骤完全一致

这个页面只是把**已经通过 Step 6 自查、已经存进 .md 文件的内容**换一种呈现方式，不产生新内容，因此不引入新的版权风险——但也正因为如此，**绝不能为了让页面看起来更饱满而现场编造原文档里没有的细节**（比如编一个"冷知识"框、编一个不确定的历史数字去填版面）。页面上出现的每一句话，都应该能在已存档的 `.md` 文件里找到对应出处。

## 触发方式

- 只在明确的请求上触发："发布成网页"/"做个可视化页面"/"生成一个交互页面看看"/"把对照表做成图"。
- 不需要像 Step 8 那样单独问范围（teaser/highlight/full）——这一步是对已有文档的完整可视化，没有"部分渲染"的概念，要么做完整的，要么不做。
- 生成完之后，把链接发给用户，并说明这是默认私有的页面，分不分享由用户自己决定。
