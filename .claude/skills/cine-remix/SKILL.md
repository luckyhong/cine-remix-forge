# 电影深度解说词 + 原创动画短片生成器 (Cine Remix)

给一个电影解说视频链接，或者直接给一个电影名字，产出两份完整的原创内容：一份有钩子、有深度、有真实历史锚点的电影解说文案，一份全新设定的原创动画短片剧本（主题上呼应这部电影，但故事完全原创）。

## 版权红线（贯穿全流程，没有例外）

这个 skill 处理的输入常常本身就是受版权保护的内容（电影台词、原著小说、别人的解说视频文案）。产出必须是**围绕这些素材的原创评论和原创改编**，不是复制粘贴：

- **电影解说词**可以自由讨论剧情、人物、历史背景，可以做剧情梗概（这是影评的常规操作，不算侵权），但**不能大段逐字引用电影台词或原著小说原文**——至多引用一处、不超过约15个字的原句，且必须是为了具体说明某个手法/金句。
- 如果输入是**别人的解说视频链接**，抓取到的转写文案只能用来提炼"这个解说用了什么钩子/论证结构"，**不能把转写文案的具体论证、比喻、段子直接改写沿用**——新解说词的论点、结构设计、修辞方式必须是重新想的，参考的是"这类内容为什么有效"的方法论，不是抄一份"参考答案"。
- **动画短片必须是100%原创的虚构故事**：新的世界观、新的角色名字、新的具体情节，不能直接把电影里的人物、场景、台词换个媒介照搬——是"主题/结构上受这部电影启发"，不是"这部电影的动画版"。判断标准很简单：如果把动画剧本拿给一个没看过原电影的人，他不应该能一眼认出"这是在讲哪部电影"。
- 历史背景信息（导演/演员/作者的真实生平遭遇、真实的历史事件）可以在解说词里自由引用，因为这些是事实，不是受版权保护的表达——但必须是你有把握的真实信息，拿不准的地方用"据记载"这类措辞留有余地，不要把不确定的细节讲得斩钉截铁，更不要编造史实。

## 工作流程

### 第一步：判断输入类型

- **给的是视频链接**：走"分支A"，先抓取参考解说视频。
- **给的是电影名字/没有链接**：走"分支B"，直接研究这部电影本身。

### 分支A：从解说视频链接起步

用 `scripts/fetch_content.py` 抓取这条参考解说视频的信息：

```bash
python3 scripts/fetch_content.py "<video_url>"
```

脚本会按"平台字幕 → 简介文案 → 本地语音转写兜底"的优先级尝试拿到文案（详见脚本内注释）。拿到内容后，只需要做一次**轻量拆解**——这个视频用了什么钩子、大致的论证走向、结尾怎么收——作为"这类解说为什么有效"的参考，不需要像通用版拆解 skill 那样做逐分钟的精细结构分析。拆解完成后直接进入第二步，设计一份完全独立的新解说词，不要在措辞和具体论证上贴着参考视频走。

### 分支B：只有电影名字

不需要抓取任何视频。直接调用你自己的知识（必要时用 WebSearch 核实关键事实），收集这部电影/剧集需要的背景信息：导演、编剧、主演、上映年代、原著背景（如果是改编作品）、真实的历史/社会背景、这部作品在真实世界里的评价或影响（如果你知道的话）。这些事实要经得起核实——拿不准的地方明确标注"据记载"或直接跳过，不要为了让解说词显得更有分量而编造具体年份、人物遭遇或评价数据。

### 第二步：设计解说词的论点和结构

不要一上来就复述剧情。先想清楚**这次解说要提出的核心论点是什么**——最好是一个和"网上常见解读"不完全一样、甚至能自圆其说地反驳常见解读的角度，这是让解说"有深度"的关键，不是靠堆砌辞藻。论点想清楚之后，再倒着设计分幕结构去论证它。

参考 [references/script_format_guide.md](references/script_format_guide.md) 里的格式规范、钩子设计模式和分幕节奏——这份参考文件里有具体的开篇钩子句式、每幕结尾的"转折句"写法、以及结尾升华的收束方式，照着这套方法论重新设计，不要照抄任何具体例句。

### 第三步：撰写完整解说词

固定格式：分幕 + 时间轴 + 【画面】/【音效】/【文案】标记（具体格式看 references/script_format_guide.md 里的模板）。

硬性要求：
- 总时长控制在 **8-16 分钟**（按口播语速，1分钟大约250-300字，据此估算总字数并往这个区间去写，不要写成三五百字的大纲糊弄过去）
- 开篇要有**钩子**：一个反常识提问、一个"先给结论再打脸"式的开场、或者一个足够抓人的场景切片，不能是"大家好，今天聊一部电影"式的平铺直叙
- 至少设计**一处跨作品对照**（和另一部真实存在的、主题相关的作品做类比或对比），这是让论证显得更扎实、更有阅片量支撑的常用手法
- 结尾要有**升华**（把电影里的具体故事，收束成一个更普世、能让观众联系到自己生活的论点），再加一句收尾的 call to action

### 第四步：设计动画短片的世界观

这一步之前先看一眼 [references/used_concepts_log.md](references/used_concepts_log.md)——里面记录了这个 skill 之前生成过的动画核心意象（比如"报时人""独轮车"这类），**这次必须换一个全新的核心意象和世界观**，不能重复用过的框架，哪怕主题类似也要用完全不同的具体载体来表现。

参考 [references/animation_fable_guide.md](references/animation_fable_guide.md) 里的寓言设计方法论：怎么找一个具体的、视觉化的"载体意象"来承载抽象主题、怎么设计首尾呼应、怎么把戏谑/黑色幽默和严肃主题做混搭而不显得轻浮。

设计完成后，在 [references/used_concepts_log.md](references/used_concepts_log.md) 里追加一行记录这次用的核心意象，供以后的运行参考避免重复。

### 第五步：撰写完整动画短片剧本

固定格式：项目信息（片名/时长/形式/基调）+ 人物列表 + 分场剧本（具体模板看 references/animation_fable_guide.md）。

硬性要求：
- 每一场都要有**画面描述**，不能只写抽象的场景概念
- 要有清晰的**首尾呼应**设计（一句台词、一个视觉符号，开头结尾各出现一次，含义或语气发生变化）
- 至少一到两处**对照/转折角色**的设计（一个质疑者、一个继承者），避免主角一个人从头到尾唱独角戏
- 台词允许带戏谑/黑色幽默，但揭示真相或情感高潮的段落要收住，不要把严肃的地方也写成段子

### 第六步：组装成完整文档

按 [references/output_template.md](references/output_template.md) 里的结构把两部分拼成一份文档：先解说词，再动画短片剧本，最后附一张"创作手法对照表"，写清楚解说词和动画剧本里各自用了什么手法、彼此有什么呼应设计——这张表是这份文档除了两份成稿之外的第三个价值点，方便用户以后自己拆解复用这套方法论。

## 边界情况

- **电影/视频信息拿不到、抓取失败**：如实告诉用户具体报错，不要在信息不全的情况下硬编详细情节去凑一份解说词。可以先把明确知道的部分写出来，标注哪些地方需要用户补充。
- **不确定某个历史/传记细节是否准确**：宁可用更保守、更模糊的措辞（"据记载""相传"），或者直接不用这个细节，也不要为了戏剧效果编造具体年份、人物结局或评价数据。
- **电影本身争议性强（政治、历史敏感议题等）**：解说词可以有明确的论点和立场，但不要替用户下最终的历史/政治结论，保留"这是一种解读角度"的分寸感；动画短片同理，寓言可以尖锐，但不要指名道姓影射现实中的具体政治实体或人物。
- **用户只要其中一份**（只要解说词，或只要动画剧本）：跳过不需要的那部分，不用强行凑齐两份。
